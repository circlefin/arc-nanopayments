Trace log persisted on the seller:
{{- if .Values.trace.existingClaim }}
  Using the existing PVC {{ .Values.trace.existingClaim }}, mounted at /app/.trace.
  The chart neither created nor sized it and does not manage its lifecycle.
{{- else }}
  PVC {{ include "arc-nanopayments.traceClaimName" . }} ({{ .Values.trace.size }}, ReadWriteOnce) mounted at /app/.trace
  Owned by this release — `helm uninstall` DELETES it and the trace log with it.
  Set trace.existingClaim to an operator-managed PVC if the log must survive.
{{- end }}
  Rollouts use maxSurge: 0, so the old pod is torn down before the replacement
  starts (a ReadWriteOnce disk cannot attach to both at once). Expect a short
  seller outage on every deploy while trace is enabled.
  Requires seller.replicas: 1.

  Check it is bound and writable by the app user (uid 1001):
    kubectl -n {{ .Release.Namespace }} get pvc {{ include "arc-nanopayments.traceClaimName" . }}
    kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "arc-nanopayments.fullname" . }}-seller -c seller -- \
      sh -c 'id; ls -ld /app/.trace; ls /app/.trace/events'

  The haia-trace CLI ships in the image and is on PATH. Build receipts from the
  recorded runs — use x402-seller, since only server-side events are captured:
    kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "arc-nanopayments.fullname" . }}-seller -c seller -- \
      haia-trace build --template x402-seller
    kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "arc-nanopayments.fullname" . }}-seller -c seller -- \
      haia-trace receipt list
  It reads .trace/events and writes .trace/receipts on this same volume, so the
  receipts persist across restarts. Add --all to rebuild every run, not the latest.

  Only SELLER-side events (verify/settle) are recorded. The buyer writes to its
  own container filesystem, so its events do not appear on the trace page —
  sharing one volume needs ReadWriteMany, which Compute Engine disks lack.
{{- end }}
